## Implemented behavior

- `ort-render` embeds Typst/typst-layout/typst-pdf 0.15.1. Its World exposes a
  single bundled source and six bundled Libertinus Serif faces from typst-assets
  0.15.1. Typed resume paragraphs enter through JSON data, never source-string
  interpolation. File/package/plugin access, font discovery and date lookup are
  denied. The original `plain_pdf_v1` template uses US Letter, one-inch margins,
  11 pt body, 18 pt name, 12/11 pt semantic headings and English layout language.
  There is no external executable, template path, user markup or remote resource.
- Validation preserves ordered professional content, visible link destinations,
  custom fields, bullets and explicit line breaks. Tabs become four spaces.
  Internal titles/IDs and personal/date PDF metadata are not exported. Invalid
  content, missing font coverage, compilation warnings, more than 800 blocks or
  200 hard breaks, more than five pages, or output above 4 MiB fails explicitly.
  Post-layout glyph bounds also reject clipping, missing shaped glyphs and
  unreviewed drawing/transform behavior. No content is silently truncated, shrunk
  to fit, or rendered using a system-font substitute.
- Main-window-only commands select an exact saved draft or published revision.
  Rendering runs off the UI thread under the shared native export lease; supported
  quit paths wait. A single memory-only preview is identified by canonical UUIDv7
  and a ten-minute validity interval. Unknown, expired and replaced tickets fail.
  Refresh clears the old native cache before compilation; token-specific release
  cannot erase a newer preview. Clear, UI expiry and unmount release the ticket.
- The frontend displays hash-verified generated bytes through PDF.js 6.3.289 and
  an explicit bundled module worker. No CDN/blob wrapper, fake-worker fallback,
  system fonts, worker fetch, WASM, XFA, annotation UI or PDF scripting is used.
  Canvas size is capped at two million pixels. Loading/page-display failures and
  ten-second UI timeouts disable export. Navigation, relative zoom, keyboard
  scrolling, accessible React text, session receipt and complete font/license
  notices are available without an iframe or HTML injection.
- PDF export accepts only a ticket. Native code checks its saved revision before
  the dialog and holds the exact bytes while the user selects a new `.pdf` name.
  It uses the existing held-directory/private-staging/no-clobber destination
  capability; no path, arbitrary PDF, template or overwrite authority crosses
  from JavaScript. New edits mark draft previews stale; published previews remain
  independent. Cancel, failure and uncertain results do not modify stored data,
  discard edits, pause autosave or silently retry. Cleanup/durability warnings
  remain distinct from a failed write.

See `docs/adr/0004-typst-rendering.md` and `docs/dependencies/pdf/README.md` for
upstream provenance and full notices. Typst adds a substantial transitive compiler
graph: 177 registry package/version entries plus the new workspace crate were
added to Cargo.lock; no prior package/version entry was removed. Image/PDF/WASM
implementation dependencies do not make their resource inputs available through
this fixed World. Typst and PDF.js use Apache-2.0; selected unmodified Libertinus
faces use OFL-1.1. Full upstream assets notices are preserved and bundled.

This is an in-process fixed-template renderer, not a sandbox or hard CPU/memory
deadline. The cache is bounded and expires on access; UI expiry/release normally
clears it sooner, but a renderer reload may leave native bytes until next access
or process exit. Memoized Typst content is evicted after each render. None of
these is secure erasure of process memory, swap, or crash dumps. Broader RustSec,
transitive-license/SBOM and signed release-package review remain open.

No SQLCipher mitigation, encryption or memory-protection setting, importer gate,
native containment harness, entitlement or application identity was changed.
`IMPORT_ENABLED=false` and worker exit 78 remain. Tauri gains only the local
worker CSP directive, no filesystem/network/dialog renderer capability. No
migration is required; existing saved records and exports are unchanged.
